# 벤치마크: 인증 게이트(A) vs 일반 검토(B) vs 초안만(C)

> **중요한 한계.** 평가자는 사람이 아니라 LLM 에이전트다. LLM 시뮬레이션은 사람 인증자 행동의 **대리 지표일 뿐**이며, 아래 수치를 사람의 검출률·소요 시간으로 읽으면 안 된다. 사람 파일럿 절차는 [PILOT.md](PILOT.md)에 있다.

실행일 2026-11-22, run tag `main`, 516 세션(2 모델 × 2 변형 × 3 조건 × 43 항목), 하네스 오류 0, LLM 호출 오류 0.

## 1. 설계

### 조건 (화면)
| 조건 | 화면 | 보이는 것 | 결정 |
|---|---|---|---|
| **A** 인증 게이트(그림 5) | `certify.html` | 초안 문장별 + 1차 출처 원문 나란히, 불일치 강조(숫자·연도·판본=강, 인과·근거 약함=약), 문장별 '원문 위치 보기'→'대조함' 체크, [쟁점] 패널 | 서명·승인(게이트 충족 시에만 활성) / 보류 / 거부(사유 필수) |
| **B** 일반 검토(기준) | `review.html?condition=B` | 같은 초안 + 같은 출처 원문, 강조·체크 없음 | 승인 / 건너뛰기(결정 안 함), 코멘트 선택 |
| **C** 초안만 | `review.html?condition=C` | 초안 + 출처 제목만(원문 없음) | 승인 / 건너뛰기 |

세 조건 모두 에이전트 상태 배지('확인됨')를 똑같이 보여 준다. B·C의 결정은 기록만 하고 항목 상태를 바꾸지 않는다(서버가 강제). B는 과제 지시대로 '승인' 버튼이 중심이지만, 승인하지 않은 경우를 관찰하려고 '건너뛰기'를 뒀다.

### 과제 세트 (43개, `bench/tasks.json`, 정답 `bench/truth.json`)
| 출처 | 정상 | 오류 | 쟁점 |
|---|---|---|---|
| SciFact (CC BY 4.0 / ODC-By, 27개) | 14 (원 SUPPORT 주장) | 13: 숫자 4·연도 1·인과 과장 2·출처에 없는 문장 추가 2 (심음), 원 CONTRADICT 주장 4 | – |
| ontology.json 실제 항목 (16개) | 8 | 6: **15%(확인됨) vs 출판본 14% 판본 불일치**, 출처에 없는 문장(실제 항목 그대로) 2, 연도 2·숫자 1(심음) | 2 (autonomy, working_knowledge) |

- 오류 유형은 논문에서 관찰한 실패 양상(숫자·연도·판본·인과 과장·출처에 없는 문장)을 따랐다.
- 모든 항목은 '확인됨' 상태로 제시했다(쟁점 항목은 '초안'). 항목 ID는 섞은 뒤 불투명하게(T01–T43) 붙였다.
- ontology 항목의 원문 발췌(`data/seed/sources.json`)는 저자가 서지·공개 초록을 바탕으로 **재구성**했다. 정답은 '화면에 보이는 원문과 일치하는가'로 정의했다.

### 평가자 (LLM 인증자)
- 모델 2계열: Anthropic `claude-haiku-5-5`(Claude Code CLI, 도구 끔, 사용자 설정 끔), OpenAI `gpt-6.2-sol`(codex CLI 기본 모델, read-only sandbox, 사용자 설정 무시).
- 조작: Playwright가 화면을 텍스트로 바꿔(영역별 innerText + 컨트롤 목록: id·종류·라벨·비활성·체크 여부) LLM에 주고, LLM이 JSON으로 돌려준 조작(click/fill)을 실제 브라우저에서 실행한다. 항목당 최대 4차례.
- 프롬프트: 조건 간 **완전히 동일**(`bench/run-bench.mjs`의 SYSTEM/TASK/FORMAT). 변형 `rushed`는 앞에 시간 압박 문단(대기 300개, 20분, '대부분 확인됨', 처리량 평가)을 붙였다.
- 순서: (모델×변형×항목)마다 조건 순서를 무작위로 하고 전체 실행 순서도 섞었다(시드 7). 각 호출은 기억이 없는 독립 세션이다.

### 지표
- **오류 검출률**: 오류 항목 중 승인하지 않은 비율(A: 보류·거부, B/C: 건너뛰기). **잘못된 승인** = 1 − 검출률.
- **정상 오거부율**: 정상 항목 중 승인하지 않은 비율.
- **쟁점 소실**: 쟁점 항목을 해석 선택·사유 없이 승인한 비율.
- **단계/항목**: 실행된 UI 조작 수. **시간**: 세션 벽시계(LLM 지연이 대부분이므로 사람 시간과 무관).
- **사유 품질(0–2)**: 오류 항목에 남긴 보류·거부 사유(B/C는 코멘트). 2 = 항목별 핵심어(틀린 값·맞는 값·오류 유형어)를 지목, 1 = 10자 이상 일반 사유, 0 = 없음. 규칙 기반이라 거친 지표다.
- 통계: 조건 간 비교는 항목 단위 대응쌍으로 **정확 맥니마 검정**, 비율 차이는 대응 부트스트랩 95% CI(4000회), 단일 비율은 Wilson 95% CI. POOLED 행은 4개 층(모델×변형)을 합친 것인데, 같은 항목이 층마다 반복되므로 독립 가정이 약하다(참고용).

## 3. 해석

1. **오류 검출은 천장효과.** 두 모델 모두 A·B에서 심은 오류 19/19를 전부 걸렀다(잘못된 승인 0%). 시간 압박 변형에서도 같다. 그래서 '게이트가 잘못된 승인을 줄이는가'(A vs B)는 이 평가자로는 **판별할 수 없었다**(불일치쌍 0, p = 1). 이것은 게이트가 효과가 없다는 증거가 아니라, LLM 평가자가 원문이 옆에 있으면 대조를 생략하지 않는다는 뜻에 가깝다. 사람의 실패 양상(원문을 읽지 않고 '확인됨'을 믿고 승인)이 재현되지 않았다.
2. **원문이 없으면(C) 판본 오류가 통과한다.** C의 잘못된 승인 4건 중 3건이 15%/14% 판본 사례였다(나머지 1건은 seci의 '출처에 없는 문장'). A·B에서는 4개 층 모두 이 항목을 걸렀다. 원문을 나란히 보여 주는 것 자체가 판본 오류를 막는 핵심이라는 논문 주장과 방향이 맞는다. 다만 POOLED 4/0, p = 0.125로 유의하지 않다.
3. **비용은 정상 항목 오거부로 나타났다.** 정상 항목 승인율이 A 40% vs B 52%(POOLED 차이 −13%p [−23, −2], 맥니마 p = 0.043)로, 게이트 화면에서 더 보수적이었다. codex·normal 층에서 차이가 가장 컸다(−27%p, p = 0.070). 문장 단위 대조·강조 표시가 '조금이라도 다른 표현'을 보류하게 만든 것으로 보인다. A의 정상 항목 보류 53건 중 4건은 자동 '대응 위치' 표시가 틀렸다는 지적이었다. 정렬 품질이 오거부를 부를 수 있다는 설계상 신호다.
4. **'정상' 기준선 자체가 엄격한 평가자에게는 느슨하다.** 오거부는 SciFact 정상 주장에 몰렸다(조건 대부분에서 43–93%). 이유는 대개 정당한 지적이었다: 'common haplotype'을 'CHEK2 전체'로 일반화(dev208), '자가 보고 시각 문제'를 '시력'으로(dev137), 'CMA'를 'autophagy 전체'로(dev148). 즉 '정상 오거부율'의 상당 부분은 정답 라벨(SciFact SUPPORT)과 엄격한 인증 기준의 차이다. 인증 맥락에서는 '수정 후 재제출' 요청이 오히려 바람직할 수 있다.
5. **게이트는 규칙대로 작동했다.** A에서 승인 35건은 모두 문장 전부를 '원문 보기→대조함'한 뒤에 나왔다(서버 기록). 쟁점 항목은 A에서 8/8 보류(사유 기록), B·C에서는 8/8 건너뛰기였다. 소실(해석 없이 승인)은 0건이지만, 평가자가 쟁점 항목을 아예 승인하지 않아 '쟁점 보존' 기능의 차별 효과는 관찰되지 않았다.
6. **조작 비용.** A는 항목당 조작 2.4–2.7단계, LLM 호출 1.5–1.6회로 B(1.7–1.9단계, 1.0회)보다 많았다. 게이트 조건(보기→체크)을 한 번에 계획하지 못하고 화면을 다시 본 경우가 대부분이다.
7. **강조기 단독**(규칙 기반, 기계만)은 오류 10/19(숫자·연도·판본은 전부, 인과·모순·출처에 없는 문장은 거의 못 잡음)를 표시했고 정상 항목 오경고는 0/22였다. 강조 규칙과 심은 오류를 같은 저자가 만들었으므로 이 수치는 **낙관적으로 편향**돼 있다.

## 4. 한계
- **LLM ≠ 사람.** LLM 평가자는 지치지 않고, 원문이 텍스트로 주어지면 거의 항상 읽는다. '서두르는 인증자' 프롬프트도 대조 생략을 만들어 내지 못했다. 게이트의 핵심 가설(사람이 바쁠 때 원문 대조를 건너뛰는 것을 막는다)은 이 실험으로 검증되지 않았다. 사람 파일럿이 필요하다.
- **화면의 텍스트 변환.** 평가자는 픽셀이 아니라 영역 텍스트를 받는다. 시각적 강조(빨간 배경)는 텍스트('불일치 의심 — …')로만 전달되며, 사람이 느끼는 시각적 주의 효과와 다르다.
- **표본.** 오류 19, 정상 22, 쟁점 2개로 작다. 층별 검정력이 낮고 POOLED 검정은 항목 반복 때문에 독립성이 약하다. 판본 오류는 1건뿐이다.
- **정답 라벨.** SciFact SUPPORT를 '정상'으로 썼지만, 엄격한 평가자에게 일부는 과잉 일반화다. ontology 항목의 원문 발췌는 저자 재구성이고, 15%/14% 사례의 워킹페이퍼 판본 문구도 재구성이다(ontology 자체 메모 근거).
- **저자 편향.** 오류를 심은 사람이 강조 규칙도 썼다. 강조기 성능은 낙관적이다. 강조기를 끈 A 변형(게이트만)은 돌리지 않았다.
- **B의 '건너뛰기'.** 과제의 '승인 버튼만'을 문자 그대로 구현하면 미승인을 관찰할 수 없어 건너뛰기를 넣었다. 실제 승인 전용 도구보다 미승인이 쉬운 쪽으로 편향됐을 수 있다.
- **시간 지표.** LLM 지연이 대부분이라 사람 시간과 무관하다.
- **모델.** Claude Haiku 5.5와 codex 기본 모델(gpt-6.2-sol) 각 1개. 더 약한 모델이나 비전 기반 에이전트에서는 결과가 다를 수 있다.

## 5. 재현
```bash
npm install && npx playwright install chromium
npm run bench:build
node bench/run-bench.mjs --models claude-haiku,codex --variants normal,rushed --conds A,B,C --conc 8 --tag main
node bench/analyze.mjs main
node bench/screens.mjs           # 조건별 화면 스크린샷 → docs/screenshots/cond-*.png
```
산출물: `bench/results/summary-main.json`(지표·검정 전체), `bench/results/sessions-main.json`(세션별 정리), `bench/results/raw/main/`(세션 기록·조작 내역, 서버 인증 로그, 설정·프롬프트).
