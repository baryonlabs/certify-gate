# 실행 전 커밋한 분석 계획: 시니어 기술직 페르소나 행동-지식 간극 시뮬레이션 v2 (커밋 `COMMIT_HASH`)

작성 2026-11-23 15:40 KST. 페르소나 추출(LLM 호출 없음)만 끝낸 상태에서, 생성·탐지·응답 LLM 호출을 실행하기 **전에** 이 문서를 커밋한다. 이후 변경은 맨 아래 '변경 기록'에만 시각·이유와 함께 추가한다.

> 이 시뮬레이션은 LLM이 연기한 합성 페르소나의 응답이다. **사람에 대한 증거가 아니다.** '기존 지식', '숨은 이유', 간극 정답 라벨도 모두 LLM이 만든 것이다.

## 1. 목적과 우선순위
논문(HCI KOREA 2027)의 흐름은 ① 행동 관찰 → ② 행동 문장으로 기존 지식(온톨로지) 검색 → ③ 검색된 항목이 그 행동의 이유(기준·조건)를 진술하는지 판정, 진술하지 않으면 '행동-지식 간극' → ④ 간극마다 질문 1개와 예상 답 3개 생성 → ⑤ 사람이 확인·교정이다. 이전 시뮬레이션(`docs/PERSONA_SIM.md`)은 간극 판정을 검증하지 않았고(정답 라벨 없음), 질문을 A 조건에만 보였고, 보충 입력이 선택 사항이었다.

이번 v2의 지표 우선순위(코디네이터 지시, 2026-11-23):
1. **1차: 간극 탐지 정확도**와 **탐지 방법 비교**
2. **1차: 질문의 겨냥 정확도**(질문이 숨은 이유의 기준·조건을 정확히 묻는가, 예상 답 적중률)
3. **2차: 끌어낸 지식의 정확도**(B / A / A+ 응답이 숨은 이유를 담은 정도)
4. **3차(보고만)**: 입력 글자 수. 시간은 측정하지 않는다(LLM 지연은 사람 시간과 무관).

실행 순서도 이를 따른다. 모든 페르소나에서 1·2단계(생성·탐지·질문·겨냥 채점)를 먼저 끝낸 뒤 응답·응답 채점을 돌린다.

## 2. 페르소나
- 출처: NVIDIA Nemotron-Personas-Korea (Hugging Face `nvidia/Nemotron-Personas-Korea`, CC BY 4.0).
- 스크립트: `bench/persona-senior/sample-personas.mjs`, 시드 20261123. HF datasets-server API가 429(요청 한도)로 막혀 parquet 샤드 2개(`train-00000`, `train-00004` of 9, 222,223행)를 받아 `parquet-to-jsonl.py`로 변환해 그 안에서 뽑는다. 후보 16,121명.
- 조건: 기술직 직무군 8개(품질·검사, 설비·정비, 전기·전자, 화학·에너지·환경, 건설·토목, IT 인프라·SW, 제조·생산, 엔지니어·기술자; 직업명 정규식) 중 하나이고, 45세 이상이거나 38세 이상이면서 직업 소개에 경력 신호어(베테랑, 수십 년, 경력, 숙련, 반장 등)가 있는 사람. 비기술직(판매·사무·교육·의료·단순 종사원 등)은 제외.
- 직무군 라운드로빈, 같은 직업·지역·성별 쏠림 회피로 **본 표본 100명(S001–S100)**과 이와 겹치지 않는 **보정 표본 10명(C01–C10)**을 고른다. 보정 표본은 방법 (c)의 임계값을 정하는 데만 쓰고 본 분석에서 뺀다.
- 직무군·직업·성별·나이 분포를 결과 문서에 기록한다.
- **축소 규칙**: 시간·사용량 한도로 못 끝내면 S001부터 순서대로 끝난 페르소나만 분석한다(최소 40명). 줄인 수와 이유를 기록한다. 1차 지표 단계(생성~겨냥 채점)를 끝낸 수와 2차 지표(응답) 단계를 끝낸 수가 다를 수 있으며, 각 지표는 그 단계를 끝낸 페르소나로 계산한다.

## 3. 모델 조합(계열 분리)
| 역할 | 모델 | 계열 |
|---|---|---|
| P: 기존 지식·판단·숨은 이유·정답 라벨 생성, 응답자(새 세션) | claude-sonnet (claude CLI) | Anthropic |
| Q: 간극 탐지(논문 에이전트), 질문·예상 답 생성 | codex CLI 기본 모델(gpt-6.2-sol) | OpenAI |
| D2: 두 번째 간극 탐지 모델(모델 간 일치도) | opencode-go/gemini-4-argon | Google |
| J-q: 질문 겨냥·예상 답 적중 채점 (Q와 다른 계열) | gemini-4-argon, claude-sonnet | Google, Anthropic |
| J-r: 응답 채점 (P와 다른 계열, 조건 모름) | gemini-4-argon, opencode-go/gpt-6-luna | Google, OpenAI |

- 채점자는 지표마다 그 산출물을 만든 모델과 다른 계열을 쓴다. 세 계열뿐이라 J-q의 claude-sonnet은 P(정답 생성자)와 같은 계열이고, J-r의 gpt-6-luna는 Q와 같은 계열(다른 모델)이다. 그래서 채점자별 결과를 따로 보고한다.
- 한 모델이 사용량 한도에 걸리면 그 모델이 맡은 단계를 멈추고, 끝난 페르소나까지만 분석한다. 모델을 바꾸면 변경 기록에 남긴다.

## 4. 절차
### 4.1 생성(P)
페르소나마다 한 번 호출해 다음을 만든다.
- **기존 지식 7개**(K1–K7): 그 직무의 사내 표준·작업 매뉴얼·점검표 수준 문서 항목(제목 + 1–2문장). 온톨로지 대용이다.
- **반복 업무 판단 12개**: 각 판단은 관찰되는 행동 문장(behavior, 이유·기준 없이 70자 이내)과 실제 이유(reason).
  - **설명됨 4개**: 기존 지식의 한 항목(k_ref)이 그 행동의 이유·기준을 명시적으로 진술한다.
  - **부분 설명 2개**: 기존 지식의 한 항목(k_ref)이 그 행동·대상은 다루지만, 이 사람이 쓰는 판단 기준·조건(수치, 상황 조건, 예외)은 진술하지 않는다. 실제 이유는 문서에 없는 암묵적 기준이다.
  - **간극 6개**: 어느 기존 지식 항목도 이유를 진술하지 않는다. 실제 이유는 경험에서 나온 구체적 암묵지(조건·수치·사례 포함)다.
  - 행동 문장에는 이유나 기존 지식의 표현을 그대로 옮기지 말라고 지시한다(표면 단서 억제).
- 라벨(설명됨/부분/간극), k_ref, 숨은 이유는 `gold` 필드로 분리 저장하며, 탐지·질문 모델에는 절대 주지 않는다. 판단 순서는 시드로 섞고 중립 ID(J01–J12)를 붙인다.
- **정답 라벨의 이진 정의(사전 지정)**: 논문 ③의 기준("검색된 항목이 이유(기준·조건)를 진술하는가")에 따라 **간극(양성) = 간극 + 부분 설명**, **설명됨(음성) = 설명됨**이다. 페르소나당 양성 8, 음성 4.
- 민감도 분석: 부분 설명을 뺀 이진 과제(양성 6, 음성 4)로도 같은 지표를 낸다.

### 4.2 간극 탐지(방법 4개, 같은 입력·같은 정답)
판정 모델 Q(codex)와 D2(gemini-argon)가 방법 (a)(b)(d)를 각각 수행한다. 방법마다 별도 호출(새 세션)이며, 페르소나의 12개 판단을 한 번에 판정한다. 출력은 판단별 `explained` 또는 `gap`.
- **(a) 논문 방식(검색 → 판정)**: 판단 문장으로 기존 지식 7개를 글자 2-gram BM25로 검색해 상위 2개를 고르고(②), 판정 모델은 판단 문장 + 검색된 2개 항목만 보고 "이 항목들이 이 행동의 이유(기준·조건)를 진술하는가"를 판정한다(③).
- **(b) 전체 지식 판정**: 검색 없이 기존 지식 7개 전체를 주고 같은 판정.
- **(c) 단어 일치 기준선(LLM 없음)**: 판단 문장과 기존 지식 항목들의 BM25 최고 점수가 임계값 τ 미만이면 간극. τ는 **보정 표본 10명**에서 F1을 최대화하는 값으로 정하고 본 표본에 고정 적용한다. 본 표본의 ROC AUC도 보고한다.
- **(d) 지식 없음**: 기존 지식 없이 판단 문장과 직무만 보고 "문서화되지 않은 암묵지에서 나온 판단일 것 같은가"를 판정.
- 방법 (a)의 검색 품질: 설명됨·부분 설명 항목에서 k_ref가 상위 2개에 드는 비율(recall@2)을 보고한다.

### 4.3 질문 생성(Q, 논문 ④)
- 대상: 정답상 양성(간극 6 + 부분 2) 8개 전부, 그리고 방법 (a)-Q가 간극으로 판정한 설명됨 항목(오탐). 논문 흐름대로 '간극으로 판정된 항목'에 대한 질문 품질은 (a)-Q 진양성 항목으로 따로 보고한다.
- 입력: 판단 문장 + (a)에서 검색된 기존 지식 2개 + 직무 맥락(직업, 직업 생활 요약). `tools/expected-answers/prompt.md` 프롬프트를 그대로 쓰고(‘그 행동 직전의 대화 맥락’ 자리에 직무 맥락을 넣음), 한 번 호출로 대상 항목을 모두 처리한다.
- 출력: 질문 1개 + 서로 다른 관점(원칙·조건·기대 결과)의 예상 답 3개(각 40자 이내).

### 4.4 질문 겨냥 채점(J-q 두 명)
항목마다 판단 문장, 숨은 이유, 질문, 예상 답 3개를 보고:
- **겨냥 점수 0–2**: 0 = 숨은 이유와 무관하거나 일반적인 '왜'만 묻는다, 1 = 숨은 이유가 다루는 영역은 묻지만 그 기준·조건까지는 겨냥하지 않는다, 2 = 숨은 이유가 다루는 기준·조건을 정확히 묻는다.
- **예상 답 적중**: 예상 답 3개 각각이 숨은 이유의 핵심 기준과 같은지(표현이 달라도 기준이 같으면 일치). 엄격 = 두 채점자 모두 같은 보기를 일치로 봄, 느슨 = 한 명 이상.

### 4.5 응답(P, 새 세션) — 2차 지표
- 대상: 정답상 간극 6개(부분 설명 제외).
- 배정: 간극 6개를 ID 순으로 2개씩 세 쌍으로 묶고, 페르소나 번호 k에 대해 쌍 j에 조건 [B, A, A+][(j + k) mod 3]을 준다(라틴 방격, 3명마다 모든 쌍이 모든 조건을 한 번씩 받음).
- 세 조건 모두 같은 질문(4.3)을 보여 준다. 조건마다 별도 호출이며, 페르소나 역할과 그 항목의 숨은 이유를 '기억'으로 준다.
  - **B**: 질문에 이유를 직접 서술.
  - **A**: 예상 답 중 선택(복수 가능) 또는 '모두 틀림'만. 텍스트 입력 없음.
  - **A+**: 예상 답을 고른 뒤 "어떤 조건에서 그런가"를 한 문장으로 반드시 보충. '모두 틀림'이면 이유를 직접 입력.
- 변형: 보통(normal)만. 시간이 남으면 바쁨(rushed)을 앞 번호 페르소나 일부에 추가하고 탐색 결과로만 보고한다.
- 최종 답 텍스트: B = 서술, A = 고른 예상 답들을 이은 문장('모두 틀림'이면 빈 답), A+ = 고른 예상 답 + 보충 문장.

### 4.6 응답 채점(J-r 두 명, 조건 모름)
페르소나의 6개 응답을 섞어 순수 텍스트로 제시한다. 판단 문장, 숨은 이유, 그 항목의 예상 답 3개(모든 조건에 동일하게 제시), 응답을 보고:
- **정확도 0–2**: 0 = 숨은 이유의 핵심 기준 없음, 1 = 일부, 2 = 핵심 기준(조건·수치 포함)을 담음
- **판단 규칙 수**: 응답에 든 서로 다른 판단 규칙 개수
- **새 기준 포함**: 응답에 예상 답 3개에 없는 판단 기준이 있는가(예/아니오)

## 5. 지표·가설·판정 규칙
분석 단위는 페르소나다. 모든 신뢰구간은 **페르소나 재표집 부트스트랩 5,000회(시드 고정) 95% 백분위 구간**이다. 탐지 지표는 페르소나를 묶음으로 재표집해 합산(micro) 지표를 다시 계산한다.

### 5.1 1차: 간극 탐지
- 지표: 정밀도, 재현율, F1(양성 = 간극), 정확도, 혼동 행렬(설명됨/부분/간극 × 판정), **부분 설명 사례의 간극 판정률**과 설명됨 사례의 정답률(특이도)을 따로 보고. 방법 × 판정 모델별.
- **H1 (지식의 기여)**: 방법 (a)의 F1이 (d)보다 높다. 판정: 대응 부트스트랩 F1 차이 (a) − (d)의 95% CI 하한 > 0. 두 판정 모델 각각 판정하고, 둘 다 충족하면 '지지', 하나만이면 '부분 지지'.
- **H2 (단어 일치를 넘는 판정)**: (a)의 F1이 (c)보다 높다. 판정 규칙은 H1과 같다.
- **H3 (검색의 손실)**: (a)와 (b)의 F1 차이가 ±0.05 안이다(동등성). 판정: 차이의 95% CI가 [−0.05, +0.05] 안이면 '동등', CI가 0을 포함하지 않으면 '차이 있음', 그 밖은 '판정 불가'.
- **H4 (경계 사례)**: 부분 설명 사례의 간극 판정률이 순수 간극 사례의 간극 판정률보다 낮다(방법 (a), 차이 CI 상한 < 0이면 지지).
- 기술 통계: 판정 모델 간 일치도(방법별 Cohen κ), 방법 (a) 검색 recall@2, 방법 (c)의 τ와 AUC.
- 주 보고값: 방법 (a), 판정 모델 Q(codex)의 F1 — 논문 파이프라인과 같은 구성이다.

### 5.2 1차: 질문 겨냥
- **M-target**: 정답 양성 8개의 겨냥 점수 평균(두 채점자 평균, 0–2)과 2점 비율. 간극/부분 별, (a)-Q 진양성 항목만으로도 보고.
- **M-hit**: 예상 답 적중률(엄격·느슨).
- 채점자 일치도: 겨냥 점수 가중 κ(2차 가중), 적중 판정 κ.
- 기술 통계만 내며 가설 검정은 없다.

### 5.3 2차: 끌어낸 지식의 정확도
- 페르소나별 조건 평균 정확도(B, A, A+; 조건당 2항목).
- **Friedman 검정**(세 조건, 페르소나 대응) 후 사후 Wilcoxon 부호 순위 검정(B–A, B–A+, A+–A, Holm 보정), 차이의 부트스트랩 CI.
- **H5 (A+ ≈ B)**: A+ − B 정확도 차이의 95% CI가 ±0.3 안이면 '동등', CI가 −0.3 아래로 완전히 벗어나면 'B 우위', 그 밖은 '판정 불가'.
- **H6 (A+ > A)**: A+ − A 차이의 CI 하한 > 0.
- 탐색: 판단 규칙 수, 새 기준 포함률, 예상 답 적중/비적중별 정확도, **앵커링**(엄격 비적중 항목에서 A·A+가 '모두 틀림' 없이 예상 답을 받아들인 비율), 직무군별 하위 분석(직무군당 페르소나 10명 이상일 때만 표로 냄), 채점자 일치도(가중 κ)와 채점자별 결과.

### 5.4 3차(보고만)
- 응답자가 직접 입력한 글자 수(B 서술, A+ 보충, A = 0).

## 6. 결측
JSON 해석 실패는 1회 재시도한다. 그래도 실패하면 그 페르소나의 해당 단계를 결측으로 두고 개수를 보고한다. 생성 결과가 형식(지식 6–8개, 판단 12개, 라벨 4/2/6)을 어기면 1회 재생성하고, 그래도 어기면 그 페르소나를 제외하고 보고한다.

## 7. 해석상 한계(사전 명시)
- 정답 라벨과 기존 지식을 같은 모델 P가 만든다. 라벨은 '생성 의도'이며 실제 문서와 행동의 간극이 아니다. 방법 (d)가 높으면 행동 문장 자체에 간극 단서가 새었다는 뜻이다.
- 응답자 P는 숨은 이유를 '기억'으로 받으므로 B가 천장에 가까울 수 있다. 응답 정확도 비교는 형식이 기억된 이유를 얼마나 손실 없이 전달하는지에 가깝다.
- 세 계열만 쓸 수 있어 채점자 하나는 생성 쪽과 같은 계열이다. 채점자별로 따로 보고한다.
