# 벤치마크 v2: 판별력 있는 게이트 평가

> 사전 등록: [PREREG_v2.md](PREREG_v2.md). 가설·분석 계획은 실험 1·3 실행 전에 커밋했다(커밋 `2307a01`). 실행 중 변경은 그 파일의 '변경 기록'에 남겼다. v1 결과(`BENCHMARK.md`, run tag `main`)는 그대로 두었다.
>
> **한계 요약.** 스크립트 정책과 LLM 인증자는 사람의 대리다. 실험 1은 '대조 증거 없이는 인증이 성립하지 않는다'는 **과정 보장**의 증명이지, 사람 판단 품질의 증명이 아니다. 실험 1에서 보듯 형식적 대조(읽지 않고 체크)는 게이트가 막지 못한다.

## 요약

| 가설 | 결과 | 근거 |

사전 등록하지 않은 부 분석에서 가장 큰 차이가 나왔다.
- **정상 항목 승인율(특이도)**: A 76% vs B 22%. 차이 +54.7%p [45.9, 61.6], 맥니마 p < 0.001.
- **정확도**: A 88% vs B 58%. 차이 +29.5%p, p < 0.001.

주의가 제한되면 B의 인증자는 원문 단락 안에서 해당 문장을 찾지 못해 '확인 불가 → 승인 안 함'으로 기울었다. A는 문장별 '원문 위치 보기'가 대응 문장을 바로 보여 주므로, 정상 항목을 근거를 갖고 승인할 수 있었다. 잘못된 승인은 두 화면 모두 이미 낮아(바닥 효과) H2를 판별하기 어려웠다.

**해석**
- **우회 차단**: A에서는 p1(즉시 승인)과 p2(첫 문장만)가 승인을 한 건도 만들지 못했다. 클라이언트 강제 활성화도 서버가 `gate_incomplete`로 거부했다. p2의 A 승인 1건은 주장 문장이 1개뿐인 항목이라 '전부 대조'와 같은 경우다.
- **B의 약한 증거**: B에서 p2는 원문을 펼쳤으므로 증거상 '우회 아님'(7건)으로 잡혔다. 하지만 B에는 문장별 증거가 없어, 펼친 뒤 읽었는지는 기록으로 알 수 없다(문장별 증거율 0%).
- **형식적 대조는 못 막는다**: p3는 읽지 않고 체크만 한 경우다. A에서 우회율 0%이고 증거도 100% 남지만, 오류 항목의 59%(24/41)가 통과했다. 강조기가 잡지 못한 유형(인과 8, 단위 6, 범위 5, 소수점 4, 판본 1)이 그대로 통과한 것이다. 게이트가 보장하는 것은 '대조 행위의 기록'이지 '판단의 질'이 아니다.
- **상한**: p4(전부 대조, 정답대로 결정)는 A·B 모두 오류 통과 0%, 정상 승인 100%였다. C는 원문이 없어 결정할 수 없었다.

**속성 기반 테스트** (`test/unit/property.test.js`)
- 무작위 항목(문장 1–4개, 쟁점 25%)에 무작위 조작 순서(보기·체크·해제·쟁점·결정, 사람/에이전트/타인 토큰, 범위 밖 인덱스, B 세션 20%)를 적용했다.

## 실험 2: 어려운 과제 세트 (`bench/v2/tasks.json`, 정답 `bench/v2/truth.json`)
- **구성**: 84개 항목. 오류 41(자릿수 7·소수점 6·단위 6·연도 5·범위 누락 5·인과 과장 8·판본 4, 판본 4개 중 1개는 실제 15%/14% 사례), 정상 43(패러프레이즈 28·표기 함정 12·판본 2개 중 출판본 수치 3).
- **출처**: SciFact corpus 초록 전문(600–2000자, ODC-By). 판본 항목은 출처 2개다. 변형 규칙은 `bench/v2/build-hard.mjs`에 있다.
- **천장 제거(구조적)**: 초안 문장은 모두 원문 앞 160자 밖에서 가져왔다. 원문은 A·B 모두 기본 접힘(요약 2줄)이라, 펼쳐야만 판별할 수 있다.
- **난이도 파일럿**: 평가에 쓰지 않는 claude-sonnet이 화면 없이 원문 전문을 보고 2회 판정했다. 라운드별 전문 판독 정확도는 95.5%, 95.5%, 93.8%였다. 바닥(2회 모두 오답) 항목은 1·2라운드에서 교체하고 3라운드 5개는 제외했다(사전 등록 변경 기록 참고).
- **천장효과의 원인**: 원문 전문을 다 읽으면 이 세트도 약 95%로 쉽다. 즉 v1의 천장효과는 과제가 쉬워서라기보다 '원문을 다 읽게 해 줘서' 생긴 것이다. v2의 난이도는 주의 제약(접힘 + 예산)에서 나온다.
- **강조기 단독**: 오류 41%(17/41)를 표시했다. 자릿수·연도는 100%, 판본 75%, 소수점 33%, 단위·범위·인과는 0%다. 정상 오경고는 5%, 표기 함정 12개 중 오경고는 0개였다(숫자 정규화가 '50 percent' 같은 표기를 흡수함). 따라서 실험 3에서 A의 이득 중 절반 이상은 강조가 아니라 '대응 위치 제시'에서 나왔다.

## 실험 3: 주의가 제한된 LLM 인증자
- **조건**: 모델 2계열(claude-haiku-5-5, gpt-6.2-sol) × 변형 2(normal, rushed) × 화면 A/B × 84항목 = 672세션.

**판정**: H2 기각 — A 0.0% vs B 3.0%, 불일치쌍 0/5, p=0.0625. H3 채택 — A 5.59 vs B 2.59 단계, A>B 298 / A<B 2 / 같음 36, p=4.43e-86.

조건 제시 순서별 정확도: 1번째 72% (241/336), 2번째 74% (250/336)

**해석**
1. **H2 기각(p = 0.063)**: 잘못된 승인은 B에서도 3%에 그쳤다. 5건은 인과 과장 2, 소수점 2, 범위 1이었다. 예산 때문에 원문을 다 읽지 못한 LLM은 '확인 불가'로 승인하지 않는 쪽을 택했다. 그래서 '서두르면 대충 승인한다'는 사람의 실패 양상은 이번에도 재현되지 않았다. A는 0/164로 방향은 가설과 맞고, A만 승인한 쌍은 0건이었다.
2. **판별력은 특이도에서 나왔다**: B의 정상 항목 오거부 135건 중 72건 이상이 사유에 '예산·생략·확인할 수 없음'을 명시했다. A는 대응 문장을 보여 주므로 정상 항목을 근거 있게 승인할 수 있었다(특이도 76% vs 22%). v1에서 '게이트 = 더 보수적'이던 결과(정상 승인 A 40% vs B 52%)가 주의 제약 아래에서는 뒤집혔다. 게이트가 대조 비용을 낮추는 쪽으로 작동한 것이다.
3. **비용(H3)**: A는 항목당 조작이 약 3단계 더 많다(보기·체크). LLM 차례는 2.4 vs 2.0회, 시간 중앙값은 18.2 vs 13.6초다(LLM 지연 포함이라 사람 시간과 무관).
4. **rushed 변형**은 두 모델 모두 A 성능을 떨어뜨리지 않았다. 시간 압박 프롬프트가 사람의 주의 부족을 흉내 내지 못한다는 v1의 관찰이 반복됐다.
5. **증거**: A 승인 131건은 모두 문장별 대조 증거가 있었다. B 승인 42건은 86%가 원문을 펼쳤지만 문장별 증거는 0%다.

## 한계
- **사람의 대리일 뿐이다**: 스크립트와 LLM은 사람의 대리다. LLM은 원문을 다 못 읽으면 승인을 보류하는 경향이 강해서, 사람의 '확인됨 표시를 믿고 승인'하는 실패가 재현되지 않았다. H2의 사람 버전은 [PILOT.md](PILOT.md) 절차로 확인해야 한다.
- **주의 예산 설계가 A에 유리하다**: A의 대응 원문 문장을 예산에서 뺀 것은 게이트 설계를 반영한 것이지만, 동시에 A에 유리한 조작적 정의다. 정렬이 틀리면 A의 이점이 줄어든다(v1에서 관찰).
- **과제 생성의 편향**: 오류와 패러프레이즈는 규칙 기반이라 문법 흔적이 남을 수 있다. 같은 저자가 과제와 강조 규칙을 만들었다. 파일럿 모델(sonnet)은 평가 모델과 다르지만 같은 계열이다.
- **표본**: 오류 41개 중 판본은 4개뿐이다. 4개 층 합산 맥니마는 같은 항목이 반복돼 독립성이 약하다.
- **사전 등록 편차**: 파일럿 교체 절차와 codex 재실행은 PREREG_v2.md 변경 기록에 있다.
