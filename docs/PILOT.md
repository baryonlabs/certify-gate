# 사람 파일럿 절차 (저자 1인, 10~15개 항목)

LLM 시뮬레이션은 사람 행동의 대리 지표일 뿐이다. 아래 절차로 저자 1인이 직접 인증하며 시간을 기록해, 같은 지표로 LLM 결과와 나란히 비교한다.

## 준비 (1분)
```bash
npm install
npx playwright install chromium   # 처음 한 번 (테스트용, 파일럿 자체는 일반 브라우저 사용)
```

## 실행 (약 20~40분)
```bash
node bench/pilot.mjs --n 12 --design ab --seed 1
# → http://127.0.0.1:5300/pilot.html 을 브라우저로 연다
```
- 12개 항목이 층화 추출된다(오류 약 45%, 쟁점 1개, 나머지 정상). 15%/14% 판본 사례는 항상 포함된다.
- `--design ab`: 항목마다 A(인증 게이트 화면)와 B(승인 버튼만 있는 일반 검토 화면)를 번갈아 배정한다. 같은 항목은 한 번만 본다(학습 효과 방지). 시드를 바꾸면(`--seed 2`) 배정이 바뀐다.
- `--design a`: 전부 A 화면. 게이트 화면에서의 소요 시간·사유만 측정할 때.
- 대기열 페이지에서 위에서부터 순서대로 연다. 시간은 화면을 연 순간 → 결정 버튼을 누른 순간으로 서버가 기록한다. 쉬려면 결정 직후에 쉰다.
- **정답(truth.json)을 미리 보지 않는다.** 판단은 화면의 원문 발췌만 근거로 한다.
- 끝나면 터미널에서 `Ctrl+C`. `bench/results/raw/pilot-<시각>/sessions.jsonl` 이 생성된다.

## 분석
```bash
node bench/analyze.mjs pilot-<시각>
# → bench/results/summary-pilot-<시각>.json, tables-pilot-<시각>.md
```
LLM 결과(`tables-main.md`)와 같은 열(검출률, 잘못된 승인, 오거부, 단계, 시간, 사유 품질)로 나온다.
사람 파일럿에서 '단계'는 화면 이벤트 수(원문 보기·체크·쟁점) + 결정 1회이다.

## 기록할 메모(선택)
- 항목마다 처음 3초 안에 '맞다/틀리다' 감이 왔는지, 강조 표시를 보기 전에 오류를 알아챘는지.
- 게이트 체크가 '읽지 않고 누르는 의례'가 된 순간이 있었는지(자기 보고).

## 해석상 주의
- n=1, 12항목이므로 통계 검정보다 **소요 시간 분포와 사례 서술**이 목적이다.
- 저자는 오류를 심은 사람이므로 맹검이 아니다. 가능하면 오류를 심지 않은 동료 1인이 같은 절차를 반복한다(`--seed` 동일).
